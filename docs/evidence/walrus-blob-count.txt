HOW TO COUNT, AND WHY THE OBVIOUS WAY IS WRONG
---------------------------------------------
recall() is a similarity search. It returns the SAME memory more than once for a
single query, so summing len(results) over the namespaces overcounts. Measured on
this account: fieldpack:945b1517 returns 34 results for 17 distinct memories.

The number below is therefore deduplicated: results are normalised (whitespace
collapsed) and counted as a set. Every figure was then cross-checked against the
local append-only journal file for that namespace, which is written before the
remote write is attempted and is the only exact listing this machine has.

  method            account total    two real-use books (old write-up)
  ----------------  -------------    --------------------------------
  raw len(results)            495    54   <- overcount, duplicates included
  deduplicated                368    43   <- correct

The write-up, the repository, and the form originally reported 54. That figure
came from the raw result count and was inflated by duplicate hits. It is corrected
here to 43 for that pair, and superseded by the per-book figures below.

METHOD IN FULL
--------------
  client = MemWalSync.create(key=..., account_id=..., env='prod')
  r = client.recall(<generic ledger query>, limit=300,
                    namespace='fieldpack:<pack_id>', max_distance=1.0)
  count = len({' '.join(i.text.split()) for i in r.results if i.text.strip()})

Namespaces were enumerated from the project's own records: every pack_id in
data/packs.json, unioned with every local journal filename.
Namespaces answered: 51/51.

max_distance=1.0 disables the distance filter on purpose. At the default threshold
the same namespaces return fewer rows, which is a second way to undercount.

A third way: the SDK's restore() summed over the same namespaces returned 9 for
this account while recall() returned three figures of magnitude more. restore()
counts what the relayer has indexed and is a lower bound, not a total. Both the
under- and over-counting directions are filed as issues on MystenLabs/MemWal.
